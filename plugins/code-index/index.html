Claude’s index to your codebase.

Claude finds your code without searching it.

a plugin for
Claude Code

When Claude Code needs a function in your project, it usually goes looking for it: searching files, opening them, reading until it finds the right one. Every time.

CodeIndex keeps a list of everything in your code: each class, function and method, the file and line where it lives, what it takes and what it does. Claude asks the list and goes straight to that line. Answers come faster and spend fewer tokens.

And it’s an opinionated linter against sloppy code. It follows A Philosophy of Software Design: deep modules, narrow interfaces. At the start of a session, and after any turn that changed code, it tells Claude what the structure broke.

    Why

    Search once. Read one line.

    grep

    Claude doesn’t keep a large project in its head. On every change it goes looking for the same names again: a grep over the tree, then files opened just to tell the definition from the calls.

      grep: every line that mentions the word, to sort by hand.
      where: the one that defines it, with what it takes and what it does.
      Mixins

      Methods are filed under the class they land in.

      members

      Big classes get split: their methods live in other files and are laid onto the class when it loads. A text search can’t see that wiring. CodeIndex reads it.

      • Recognized wiring: Object.assign(T.prototype, S.prototype), mixInto(T, S), applyMixins(T, [A, B]).
      • Found by where it lands: where UserStore.saveUser answers with the method in user-methods.js.
      • Stale copies stay out: a leftover old/ copy of the class doesn’t pass for the real one.
        Lint

        An opinionated linter against sloppy code.

        lint

        It follows A Philosophy of Software Design: deep modules, narrow interfaces. A deep module hides a lot behind a few calls, so Claude and you only need to know those calls. The same index shows where that breaks: files that need each other in a ring, classes whose insides are used from outside, modules that hide nothing, big files that are several modules in one. After deslop-please (Rust), for every language ctags reads.

        • At session start: the hook lints the whole project and shows what it found.
        • After a piece of work: when a turn edited files, a Stop hook runs lint --new and hands Claude only what that change broke, once.
        • Fixed from first principles: the skill asks which layer each piece belongs to and what clients really need, not for code moved to silence it.

        sched/policy.js ↔ queue/ring.js

        Files that import each other in a ring. Move what closes the ring to the file that uses it.

        module-cycle

        Click a diagram to hold it and step between before and after.

        kernel.js: Tasks ↔ Timers

        Two classes of one file, each using the other. A layer above calls both.

        tangle

        RunQueue.items ◀ 4 places

        A class’s fields written or reached into from other files. A plain read is no leak. Hide them behind a few calls.

        field-leak

        app.js → 7 of 8 in store.js

        One client calls most of a file’s functions: the module hides nothing. Give it a few calls that say what the client wants.

        shallow-module

        summarize.mjs: 206 functions, 10 groups

        A big file whose functions fall into groups that never call each other: modules living in one file. Shared helpers are set aside first.

        hidden-modules
        How

        Two plain tools, one index.

        index

        universal-ctags reads the definitions in about 150 languages, SQLite keeps them. A hook refreshes the index at the start of every session, and only files whose content changed are read again. No AI anywhere in it: the doc is the comment already in your source.

          Secretary

          Hand in hand with The Secretary.

          secretary

          CodeIndex knows where every name lives; The Secretary remembers what was said about it. Install both and each one reads the other, with nothing to configure. Each still works alone.

          ( ∵◐ ᴗ ◐∵ ) CodeIndex ████████████████ 42% · Opus 5.5 medium
          • The status line: while a long index runs, CodeIndex takes over The Secretary’s bar, with its own face.
          • Handoffs name functions: store/user-methods.js (changed: _loadUser, saveUser) tells the next session what each edit touched.
          • Recall by symbol: ask The Secretary about saveUser and it also finds the conversations about the file that defines it.
          Install

          Install.

          install

          Needs Node.js 22 or newer and universal-ctags (the BSD ctags that ships with macOS won’t do). macOS or Linux.

          1 · ctags
          brew install universal-ctags            # macOS
sudo apt-get install universal-ctags    # Debian / Ubuntu
          2 · CodeIndex: engine, skill, hook and a CLAUDE.md note
          git clone https://github.com/microbians/AI.SKILLS.git
bash AI.SKILLS/plugins/code-index/install.sh

          Then start a session: the first one builds the index, the next ones refresh what changed. The database adds itself to the project’s .gitignore. Re-run the installer to upgrade; install.sh --uninstall removes it.

          Limits

          What it doesn’t do.

          limits

          It indexes definitions; it doesn’t run or understand the program.
